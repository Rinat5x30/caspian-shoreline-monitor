## Формат

Заголовок (до первой строки данных): строки вида `значение : описание`, затем комментарии с `c`, затем описание 16 колонок (`Column N: ...`). Строка данных, 16 полей через пробелы:
`TOPEX   3 19921016  13  7   -0.01  0.042  10.60 TMR DOR ERA 4 0 0   -26.59   0`

Колонки: 1 миссия, 2 цикл, 3 дата YYYYMMDD, 4 час, 5 минута, **6 высота относительно среднего уровня опорного прохода Jason-2 (м; нет данных = 999.99)**, 7 ошибка (99.999), 8 обратное рассеяние (999.99), 9-11 поправки (влажная тропосфера, ионосфера, сухая тропосфера), 12-13 режим прибора, 14 флаг возможного льда (1 = лёд), 15 высота в датуме EGM2008 (9999.99 = нет), 16 источник данных (GDR=0, IGDR=1).

Для работы используется только колонка 6 (относительная высота). Колонка 15 (EGM2008) не используется: абсолютные высоты проект не заявляет.

## Поиск скачков (`detect_jumps`)

Метод (с учётом пропусков по времени): миссии усредняются по датам; для каждой даты t сравниваются медиана наблюдений в [t, t+30 суток) и медиана в [t-30, t); окно меньше 2 дат (пропуск данных) не оценивается; последовательные срабатывания сводятся к одной дате с наибольшим разрывом средних; порядок детерминирован (сортировка по дате, затем по миссии). Одиночные выбросы и пары одной даты ступенью не считаются.

Шум окон на реальном ряде: медиана 0.06 м, 95-й процентиль 0.15, 99-й 0.19, максимум 0.23. **Порог 0.20 м** (около 99-го процентиля шума). Находки при 0.20: 2001-10-01, 2016-05-10, 2021-10-14, 2025-10-01 (на уровне хвоста шума, на границы миссий не приходятся). При 0.30 м скачков нет. Вывод: ступеней порога 0.30 м и выше за 1992-2026 нет; шум уровня около 0.05 м на наблюдение, годовой сигнал 0.1-0.3 м/год.

## Landsat water composite

Код: `caspianwatch.landsat` (`season_water_mask`). Только маски воды; положения берега и сравнение с уровнем моря здесь не считаются.

- Источник: Microsoft Planetary Computer, коллекция `landsat-c2-l2` (Landsat Collection 2 Level-2, поверхностное отражение), анонимная подпись, без аккаунта. Сенсоры: Landsat 5, 7, 8, 9.
- Отбор сцен: только уровень T1 (`landsat:collection_category` = T1; T2 и RT не берутся), `eo:cloud_cover` <= 50 (то же, что в `season.USABLE_SCENE_MAX_CLOUD`), дата в месяцах сезона из `data/caspian/season.json` (июль-август) данного года. Сцена без облачности или уровня исключается.
- `MIN_SCENES = 3` РАЗНЫХ дат съёмки над участком (несколько тайлов одной даты считаются один раз); тайлы одной даты мозаичатся (первый годный пиксель в порядке id сцены). Дата без единого годного пикселя на сетке участка не считается. Меньше 3 дат: результат `None`, в кеш не пишется.
- Полосы: green и swir1. L5/L7: SR_B2, SR_B5; L8/L9: SR_B3, SR_B6 (в STAC активы `green`, `swir16`; имена полос в `eo:bands` TM_B2/TM_B5, ETM_B2/ETM_B5, OLI_B3/OLI_B6; номер полосы сверяется, несовпадение даёт ошибку). Отражение = DN * 0.0000275 - 0.2 (то же значение scale/offset в метаданных активов); DN 0 = пустое значение (маска); отражение вне [-0.2, 1.6] маскируется.
- QA_PIXEL: маскируются биты 0 (пусто), 1 (расширенное облако), 2 (перистое), 3 (облако), 4 (тень облака). Бит воды (7) для классификации НЕ используется: это собственный классификатор продукта, а не наш метод.
- MNDWI = (green - swir1) / (green + swir1) по сцене на общей сетке 30 м EPSG:32639, выровненной по кратным 30 м, покрывающей прямоугольник всех сохранённых профилей участка (начала и концы) плюс 500 м. Передискретизация: билинейная для отражения (пустые DN исключаются из ядра), ближайшая для QA. Пиксельные границы тайлов Landsat сдвинуты на половину пикселя (15 м) относительно этой сетки, поэтому билинейная передискретизация усредняет примерно 2x2 исходных пикселя (а не тождественна); сцены из зон UTM 38 и 40 перепроецируются. Дополнительное правило определённости: пиксель с green + swir1 <= 0 не годен (MNDWI не определён).
- Композит = медиана по годным наблюдениям пикселя за сезон; пиксель с менее чем 2 годными наблюдениями = нет данных (`valid` False): не суша и не вода.
- Landsat 7 после 2003-05-31 (SLC-off): сцены используются; пропуски полос = пустые значения, маскируются и заполняются медианой по остальным сценам; при менее 2 наблюдений остаются нет данных. Синтетический тест показывает, что полосы не дают суши.
- Порог воды: Оцу по композиту MNDWI на годных пикселях прямоугольника участка (256 интервалов на [-1, 1], середина плато максимума межклассовой дисперсии), порог ограничен [-0.2, 0.4]; вода = MNDWI > порог. Порог и список сцен пишутся в запись кеша.
- Кеш: `data/raw/cache/caspian/landsat_water_<site>_<year>.npz` (вне git), запись атомарная; в ней все параметры расчёта (коллекция, уровень, сезон, фильтр облачности, биты QA, метод и границы порога, соответствие полос, сетка и разрешение, MIN_SCENES), порог, даты и id сцен, маски `water` и `valid`. Несовпадение параметров или нечитаемая запись = промах. Ошибка поиска или чтения сцены даёт исключение и ничего не кешируется; повторы только для 429/5xx/OSError.
- Расширение интерфейса относительно плана: у `WaterMask` добавлены `valid` (>= 2 наблюдений; ниже по цепочке нет данных и суша различаются) и `threshold`.

Реальный прогон (2026-11-19, 3 участка x 2000-2025 = 78 участко-лет, весь кеш прогрет): `None` у gizilaghaj 2003 и lankaran_astara 2003 (в сезоне только 2 даты T1 с облачностью <= 50, обе Landsat 7 SLC-off). Порог Оцу -0.039 ... 0.227 (на границах [-0.2, 0.4] ни разу); дат на участко-год 3-16; доля годных пикселей >= 0.956 везде, кроме kura_delta 2003 (0.47: три даты, все SLC-off). ## Sentinel-2 QC

Записано 2026-11-19 00:43 +0400, ДО реального прогона Task 7. Код: `caspianwatch.sentinel` (`season_water_mask_s2`, `sentinel_displacement_series`, `qc_against_landsat`). Назначение: межсенсорный контроль положения берега по Landsat. Две линии берега используют одну сетку, сезон, композит, правило Оцу и профили, поэтому контроль показывает согласованность двух оптических сенсоров при одном методе, а не точность относительно наземной истины. Данные уровня моря не используются и не просматриваются. Решения ниже не меняются после просмотра результатов.

- Источник: Microsoft Planetary Computer, коллекция `sentinel-2-l2a` (Sentinel-2 Level-2A, поверхностное отражение), анонимная подпись, STAC-элементы уровня тайла MGRS. Годы 2017-2025, сезон июль-август из `data/caspian/season.json`.
- Полосы: green B03 (10 м), swir1 B11 (20 м), классификация сцены SCL (20 м). Отбор сцен: `eo:cloud_cover` <= 50 (как у Landsat); сцена без облачности исключается.
- Отражение: приоритет у метаданных `raster:bands` (scale/offset) актива, если они есть; иначе правило: baseline обработки `s2:processing_baseline` >= 04.00 даёт отражение = (DN - 1000) * 0.0001, baseline < 04.00 даёт DN * 0.0001 (без смещения BOA_ADD_OFFSET). Правило применяется по сцене. DN 0 = нет данных (маска). Отражение вне [-0.2, 1.6] маскируется. Сцена без `s2:processing_baseline` при отсутствии `raster:bands` даёт ошибку.
- Находка проверки метаданных (одна выборка элементов 2017, 2019, 2022, 2025 над Апшероном до прогона): `raster:bands` у активов B03/B11 в STAC нет (есть только `eo:bands`), значит действует правило по baseline. Элементы 2017 и 2019 имеют baseline 02.12 (пересчёт 2020-2021), 2022 и 2025: 04.00, 05.10, 05.11. Для одной даты и тайла бывают два элемента с разными baseline (например 2022-08-31: 05.10 и 04.00); они считаются одной датой и мозаичатся как тайлы одной даты (первый годный пиксель в порядке id сцены).
- Маска облаков и качества по SCL: маскируются классы 0 (нет данных), 1 (насыщение), 3 (тень облака), 8 (облако, средняя вероятность), 9 (облако, высокая), 10 (тонкие перистые). Классы 2, 4, 5, 6, 7, 11 не маскируются (7 = неклассифицированное не маскируется).
- Сетка: ТА ЖЕ сетка 30 м EPSG:32639, что у маски Landsat участка (`landsat.site_grid`). Обе полосы B03 и B11 передискретизируются на неё УСРЕДНЕНИЕМ (average, площадное; B03 10 м и B11 20 м усредняются на 30 м; пустые DN исключаются из ядра). SCL передискретизируется ближайшим соседом на 30 м: 30-метровый пиксель недействителен, если SCL ближайшего исходного пикселя в маскируемом классе. Это грубый выбор: SCL 20 м берётся одной точкой, а не по доле, поэтому у границы облака маска может быть смещена до 15 м.
- Композит и порог без изменений относительно Landsat: `MIN_SCENES = 3` РАЗНЫХ дат (иначе `None`, в кеш не пишется), мозаика тайлов одной даты, дата без годных пикселей не считается, медиана по годным наблюдениям, не менее 2 годных наблюдений, Оцу на годных пикселях композита с границами [-0.2, 0.4] (те же константы), вода = MNDWI > порог, MNDWI = (green - swir1) / (green + swir1) при сумме > 0. Ворота пригодности участко-года те же (не менее 3 дат с долей >= 0.1 и композит >= 0.8). Годы Sentinel-2 с менее чем 3 датами (охват до 2018 может быть редким) дают `None` по тому же правилу.
- Положение берега: `shoreline.profile_position` с теми же правилами. Ряд Sentinel-2 считается на ПОЛНОМ наборе профилей участка по Landsat (`fixed_profiles`), чтобы сравнивались одни и те же профили. Контроль сравнивает положения участко-лет (среднее расстояние от начала профиля, не смещение от базового года).
- Контроль: `qc_against_landsat(landsat, s2, site_id, tolerance_m=30.0)`: общие годы с конечными значениями в обоих рядах, медиана модуля разности <= 30 м даёт `ok`; менее 3 общих лет: `ValueError`. Участки, не прошедшие контроль, ПОМЕЧАЮТСЯ, не удаляются. Дополнительно (не критерий): средняя знаковая разность (S2 минус Landsat), разности по годам, порог каждого композита.
- Кеш: `data/raw/cache/caspian/sentinel_water_<site>_<year>.npz` (вне git), запись атомарная, в записи все параметры (коллекция, сезон, облачность, классы SCL, схема отражения, метод и границы порога, передискретизация, сетка, MIN_SCENES), порог, даты и id сцен, маски `water`, `valid`, композит MNDWI. Несовпадение или нечитаемая запись = промах; None, NaN и частичные результаты не кешируются; ошибка поиска или чтения даёт исключение; повторы только для 429/5xx/OSError.
