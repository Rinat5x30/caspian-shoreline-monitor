# Источники данных урожайности пшеницы

Файл `yields.csv`: `region_id,year,yield_c_ha`. Единица: центнер с гектара (100 кг/га), пшеница (озимая и яровая вместе), все категории хозяйств.
Единица наблюдения: район (rayon) или город республиканского подчинения. Агрегаты (экономические районы, республика) не включены, чтобы не дублировать данные.

## Источник

Государственный комитет по статистике Азербайджана (State Statistical Committee), ежегодник «The Agriculture of Azerbaijan», таблица 2.187 «Yield of wheat, 100 kg/ha».

| Выпуск | Годы в таблице | URL | Дата получения |
|---|---|---|---|
| 2024 | 2020-2023 | https://www.stat.gov.az/menu/6/statistical_yearbooks/source/agriculture_2024.pdf (стр. 511-512 печатной нумерации) | 2026-11-18 |
| 2026 | 2022-2025 | https://www.stat.gov.az/menu/6/statistical_yearbooks/source/agriculture_2026.pdf (стр. ~504-505) | 2026-11-18 |

Страница со списком выпусков: https://www.stat.gov.az/menu/6/statistical_yearbooks/?lang=en

## Обработка

- Значения извлечены из PDF скриптом (pdfplumber), привязка числа к строке по вертикальной координате относительно английской подписи района. Текстовый режим pdftotext -layout смещает значения на строку, поэтому не использовался.
- Пересчёт «валовой сбор / площадь» не применялся: значения урожайности взяты как опубликованы.
- Годы 2022 и 2023 есть в обоих выпусках; значения совпали для всех строк таблицы (проверка выполнена скриптом) (проверка на согласованность извлечения). Для остальных лет значения взяты из единственного выпуска, где они есть.
- Названия районов: «Khojavend»/«Khojavand» и «Zangezur»/«Zangazur» приведены к написанию выпуска 2024.

## Покрытие

- 66 районов и городов, по 6 лет каждый (2020-2025), 396 строк. **Лет меньше 8: в плане использовать один предиктор.**
- Исключены единицы с пропусками («-») в опубликованных данных: Ganja city (2022, 2024, 2025), Dashkasan (2022), Khojavand (2021), Mingachevir city (2021-2025), Aghdara (нет 2022-2023, новый район).
- Выпуски 2022 и раньше (годы до 2019) по прямым ссылкам не найдены (сервер возвращает HTML-заглушку), поэтому ряд короткий.
- Низкие значения в ряде освобождённых районов (Jabrayil, Lachin, Zangilan, Kalbajar, Gubadli, Khojaly и др.) опубликованы официально; причины (освоение земель, а не погода) не проверялись, влияние на валидацию стоит проверить.

## Прочие просмотренные источники (данных для ряда не дали)

- IAMO WP5 Report Azerbaijan (https://lsg.iamo.de/microsites/lsg.iamo.de/fileadmin/Dokumente/WP5_Report_Azerbaijan.pdf): таблиц урожайности нет; ссылается на районную статистику SSC 2000-2019, но сами данные не приводит.
- IAMO TR_Azerbaijan.pdf: районного ряда урожайности пшеницы не найдено (поиск по тексту).
- FEWS NET country book: страница по найденным ссылкам недоступна (404).

# Геометрия районов и маска пашни (Task 3)

## Границы

geoBoundaries gbOpen, AZE ADM2 (79 единиц, год представления 2020, сборка 2023-12-12). API: https://www.geoboundaries.org/api/current/gbOpen/AZE/ADM2/. Исходник границ geoBoundaries: Wikipedia (administrative divisions of Azerbaijan), лицензия CC BY-SA 3.0; при публикации карты нужна атрибуция. Скачивается кодом в `data/raw/cache/` (в git не коммитится).

Сопоставление: `region_aliases.csv` (`region_id,geometry_name`), составлено сверкой названий по реальному списку `shapeName`. Из 66 id в `yields.csv` 65 сопоставлены с геометрией; 1 id (`lankaran`) исключён явно (`EXCLUDED_IDS` в `src/wheatwatch/regions.py`), без догадок о геометрии.

Решения по неоднозначным названиям. Проверка по ежегоднику 2024 (табл. 2.187, стр. 511-512 печатной нумерации), дословные подписи строк:
- `Şəki rayonu ... Shaki district`, `Şuşa rayonu ... Shusha district`, `Yevlax rayonu ... Yevlakh district`, `Lənkəran rayonu ... Lankaran district`. Отдельных строк «Shaki city», «Shusha city», «Yevlakh city», «Lankaran city» в таблице нет (города в таблице: только `Nakhchivan city`, `Ganja city`, `Naftalan city`, `Mingachevir city`). Значит `shaki`, `shusha`, `yevlakh` — это районы и сопоставлены с ADM2 «... District» (площади 2306/296/1278 км2 против 12-28 км2 у городов). Города Shaki, Shusha, Yevlakh, Lankaran City, а также Baku, Sumqayit, Shirvan, Khankendi остаются без статистики.
- **Исключён `lankaran`.** Строка таблицы — именно район. В ADM2 название «Lankaran District» встречается дважды (542 и 608 км2, несмежные полигоны, оба соприкасаются с Masally), сумма 1150 км2. Независимый источник (https://en.wikipedia.org/wiki/Lankaran_District, проверено 2026-11-18): площадь района 1,540 км2, город Lankaran технически не входит в район. Ни один полигон, ни их объединение не соответствуют 1540 км2, так что принадлежность полигонов району не подтверждена; id исключён из валидационного набора. Причина дублируется в `EXCLUDED_IDS`.
- Все прочие 65 id сопоставлены один к одному по названию; `load_regions` падает при дублях в алиасах, при двух id на одно имя геометрии и при расхождении набора загруженных id с запрошенным.

## Исключённые из геометрии id

| region_id | причина |
|---|---|
| lankaran | двойной полигон «Lankaran District» в ADM2 (1150 км2 против 1540 км2), принадлежность не подтверждена |

## Атрибуция (для приложения и документации)

- Границы районов: geoBoundaries (Runfola et al. 2020, https://www.geoboundaries.org), gbOpen AZE ADM2, лицензия CC BY-SA 3.0 (источник Wikipedia). ShareAlike: производные данные границ (например, упрощённый GeoJSON или карта с ними) нужно распространять на тех же условиях CC BY-SA.
- Маска пашни: ESA WorldCover 2021 v200, лицензия CC BY 4.0. Подпись: «Contains modified ESA WorldCover 2021 data © ESA WorldCover project / Contains modified Copernicus Sentinel data (2021) processed by ESA WorldCover consortium».

## Маска пашни

ESA WorldCover 2021 v200 (10 м), Microsoft Planetary Computer STAC, коллекция `esa-worldcover`, актив `map`, анонимный доступ через `planetary_computer.sign_inplace`. Класс 40 = Cropland. Кеш: `data/raw/cache/worldcover2021_cropland_az_100m.tif` (в git не коммитится).
Растр пересэмплирован до сетки 1/1200 градуса (около 71 x 93 м на широте Азербайджана; файл 4 МБ, смоук-запуск 134 с) методом mode (мода класса в ячейке) и хранится как uint8-растр классов (0 = нет данных), bbox 44.7-50.7 E, 38.3-42.0 N (чуть шире страны). Полигоны районов маской не обрезаются.

# Климат сезона (Task 4)

Open-Meteo Historical Weather API (https://archive-api.open-meteo.com/v1/archive), без ключа и аккаунта. Суточные `precipitation_sum` и `temperature_2m_max`, реанализ ERA5 (сетка около 25 км, внутри API интерполируется к точке), часовой пояс GMT. Одна репрезентативная точка на район (`geometry.representative_point()`, всегда внутри полигона). Окно сезона: 1 марта - 30 июня включительно (`SEASON_START`/`SEASON_END` в `src/wheatwatch/climate.py`); `precip_mm` = сумма за окно, `tmax_mean_c` = среднее за окно. Пропуск (null) хотя бы одного дня окна даёт NaN за район-год, а не ноль; число пропусков пишется в лог. Кеш: `data/raw/cache/climate_{region_id}_{year}.json` (в git не коммитится).

Ограничения: значения ERA5 сглажены по ячейке около 25 км, а точка одна на район, поэтому локальные ливни и горный рельеф в больших районах отражены грубо. Это реанализ, не измерения станций.

Атрибуция: погодные данные Open-Meteo.com (https://open-meteo.com), лицензия CC BY 4.0; содержат модифицированные данные Copernicus Climate Change Service (ERA5, Hersbach et al. 2023). Подпись: "Weather data by Open-Meteo.com (CC BY 4.0), based on ERA5 from Copernicus Climate Change Service / ECMWF". Некоммерческое использование бесплатно; ссылка на источник обязательна.

ВАЖНО: сырые уровни ERA5 в горных районах смещены (одна точка на район, сетка около 25 км; например guba 2022: tmax около 8 C). Признаки для модели ОБЯЗАТЕЛЬНО строить как стандартизованные аномалии по району (z-score), а не по сырым уровням. Суточные агрегаты считаются по суткам GMT. Запись кеша хранит окно, переменные и источник; при их изменении кеш считается промахом. Район-годы с NaN не кешируются и перезапрашиваются при следующем вызове.
